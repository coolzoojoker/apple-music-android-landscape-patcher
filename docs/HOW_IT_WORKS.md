# 解包、改写、重打包：补丁器如何工作

这不是 Apple Music 源代码编译。Apple Music Android 客户端是闭源应用，本项目对使用者自行取得的指定 APKM 做可重复、可校验的二进制补丁。

## 整条流水线

1. **校验输入**：`build.ps1` 先计算 APKM 的 SHA-256。不是指定的 6.5.0 (1580) 就停止，避免把旧偏移或旧类名套到新版本。
2. **解开 APKM**：APKM 本质上是包含 `base.apk`、CPU split 和 DPI split 的 ZIP 容器。
3. **选择配置**：根据 TV / 车机和 ARMv7 / ARM64，只挑需要的 CPU 与密度模块。
4. **合并 Split APK**：APKEditor 把 base 和选定 split 合并成单 APK，方便不支持 APKM 的电视和车机安装。
5. **反汇编代码**：Apktool 以 `-r` 保留原始资源表，只把 DEX 反汇编成 Smali。这样能减少不必要的资源重编译差异。
6. **应用 Smali 补丁**：`patch-smali.ps1` 按“类名 + 原始锚点 + 唯一匹配次数”修改入口。少于或多于预期次数都会停止，不会猜测着继续。
7. **编译原创控制器**：`src/tv` 和 `src/car` 下的 Java 源码由 `javac` 编译，再由 Android `d8` 转换为新的 DEX。
8. **注入新 DEX**：新 DEX 作为下一个 `classesN.dex` 写入，不覆盖原版已有 DEX。
9. **车机清单处理**：车机配置会添加一个不导出的初始化 Provider，用于沉浸式系统栏处理；TV 配置不加。
10. **重打包与对齐**：Apktool 重建 APK，`zipalign` 做 4 字节对齐。
11. **本地签名**：首次运行在 `.local/signing` 生成每位使用者自己的 RSA 密钥，`apksigner` 签名并立刻验证。
12. **输出哈希**：最终 APK 写入 `dist`，同时显示 SHA-256，便于记录和比对。

工具、版本、下载地址及哈希都固定在 `tools.lock.json`。想看实际命令，可直接阅读 `scripts/build.ps1`；脚本运行时也会把每条非敏感命令打印到终端，签名密码会被替换成 `<redacted>`。

## 目录对应什么

- `patches/targets.json`：支持的上游版本、包名和输入哈希说明。
- `scripts/patch-smali.ps1`：对原始 Smali 入口做最小修改，带唯一锚点检查。
- `src/tv/`：横屏播放器布局、交互和状态控制的原创 Java 源码。
- `src/car/`：车机窗口 / 系统栏适配的原创 Java 源码。
- `scripts/build.ps1`：合并、解包、编译、注入、打包、签名的主流程。
- `scripts/audit-release.ps1`：检查误提交的 APK、DEX、密钥、本机路径、局域网地址等。

## 添加自己的改动

1. 新建 Git 分支，不要直接在稳定分支试验。
2. 把原始 APKM 放在仓库之外，或至少确认它被 `.gitignore` 排除。
3. 使用 `build.ps1 -KeepWork` 保留一次临时解包目录，先只读定位目标类与调用链。
4. 优先在 `src/tv` 或 `src/car` 的原创控制器中实现新逻辑；只有必须接入原版生命周期时才改 Smali。
5. 新 Smali 改动必须同时写：目标文件、旧锚点、替换内容、期望匹配次数。不能使用“全局替换后看起来能跑”的方式。
6. 不要复制或提交原版完整 Smali、资源、图片、DEX 或反编译工程；仓库只保留实现补丁所需的原创代码和最小转换规则。
7. 至少构建一个 TV 和一个车机配置。按真实功能矩阵测试普通歌、无歌词歌、队列和视频歌曲。
8. 运行 `scripts/audit-release.ps1`，再检查 Git diff 中是否出现本机路径、账号、IP、日志、签名文件或生成 APK。
9. 修改支持的 Apple Music 版本时，视为一次新移植：重新记录输入哈希、重新定位每个锚点并完整回归，不能只改版本号绕过校验。

## 为什么不直接发布预先修改好的 APK

预先修改的 APK 会重新分发 Apple 的程序代码和资源，也会让所有使用者依赖发布者的签名密钥。当前方案只发布补丁逻辑，由使用者在本机提供基础包并生成自己的签名，能更清楚地区分原创补丁与第三方专有内容。

这不是法律意见。发布者和使用者都应自行遵守所在地法律、Apple 服务条款、基础包来源条款与各构建工具许可。

## 调试资料如何去隐私

公开 Issue 前只保留与问题有关的时间段，并删除或替换：

- Apple ID、邮箱、真实姓名、手机号和付款信息；
- Windows 用户目录、电视 / 车机 IP、ADB 序列号、Wi-Fi 名称；
- 媒体库中不想公开的歌曲、播放列表和封面；
- `.local/signing`、密码文件、证书私钥和任何生成 APK。

演示视频同样只录制补丁器窗口和专用演示目录，不录浏览器账号、GitHub 授权页、电视调试授权弹窗或个人媒体库。
